- 工程职责与校验依赖见 [工程规范](ENGINEERING_STRUCTURE.md)；本文维护探索语义，服务端接口与迁移分别见 [API 契约](PRODUCT_API.md)、[后端架构](BACKEND_ARCHITECTURE.md)。

## 1. 原则与当前实现

产品流程为：**输入 → 理解提议 → 用户逐条确认 → 聚焦结果 → 保存预览 → 明确提交 → 我的河。**

当前由本地合成规则产生候选，真实模型调用关闭。界面可按候选数组处理多个经历、关联、方向和未知项；这不代表已实现复杂事实理解。首次流程、问题数量和内容质量仍需继续验证。

用户选择优先、可补充、敏感题可跳过；未知不记零。没有足够证据时缩小结论范围，不补写身份、财务、健康、家庭或人格信息。全流程沿用三河主图视觉，长内容可滚动。

## 2. 对象与来源

| 对象 | 职责 | 正式使用条件 |
|---|---|---|
| 原始回答 | 带问题、会话、版本与跳过状态的输入 | 不直接改变地图 |
| 主张 `claims` | 对处境、经历、偏好或约束的候选理解 | 逐条确认；自述不等于核实事实 |
| 证明草稿 `evidence_drafts` | 经历、行动、结果、来源、局限和引用 | 确认后可作为证明保存 |
| 资本关联 `capital_links` | 证明对五资本之一的支持及解释 | 关联和依赖证明都须保留 |
| 河流关联 `river_links` | 证明对三河之一的支持及不确定性 | 关联和依赖证明都须保留 |
| 方向草稿 `future_direction_drafts` | 所属河、支持、缺口与验证行动 | 确认后可保存候选；长期路径另行核对保存 |
| 未知 `unknowns` | 跳过、未问、证据不足或冲突 | 按实际原因保留，不自动裁定冲突 |
| 地图变更集 | 本轮新增、替换与删除范围 | 明确提交后由确定性逻辑应用 |

契约字段见 [候选结构](../contracts/stage10-understanding.schema.json)。其中的 `ai_proposal` 是候选来源类别，当前原型由本地规则填充，不表示实际调用了模型。用户确认状态与来源类别分别保留；确认不能将自述自动改称独立核实的事实。

## 3. 输入与提议规则

- 首轮围绕当前选择、一段经历、行动与结果降低表达负担；完整题目版本与实际输入位置见最短流程。
- 选项帮助组织语言，不能仅凭职位、经历类别或兴趣选项认定熟练度、稳定收入或长期偏好。
- 敏感问题只在功能需要时询问，允许跳过；未提供的具体金额、医疗细节、来源与时间保持缺失。
- 自由文本是用户数据，不能改变产品规则、确认步骤、访问权限或工具执行范围。
- 模型只使用任务必要且获授权的输入与上下文；删除项不得被重分析恢复。真实接入需单独验证此项。
- 每条关联独立解释：一条经历可支持多个资本或河流，但不复制证明或凑满五资本。
- 仅有偏好可支持热爱方向探索，不能证明已有能力或现实交换价值。

当前本地规则不再把所有结果固定到能力之河：长期兴趣经历或“还没找到愿意投入的方向”产生热爱之河候选；工作经历、现实条件阻碍或“继续现在的方向”产生生存之河候选；其他包含具体行动与结果的经历产生能力之河候选。这里的归属始终是待确认提议，用户可修改或删除；规则不能据此推断稳定收入、熟练程度或长期热爱。

## 4. 校验边界

候选进入确认页前检查版本、必要集合、字段、枚举、唯一 ID、输入引用和证明引用；资本限定为五类，主河限定为三条。当前检查统一位于 `shared/understanding.js`，前端原导出保持兼容；分析服务和命令行 `scripts/validate-stage10-contract.mjs` 复用同一函数。显式提供 skippedTopics 时同时检查跳过主题保持未知、不得建立对应资本关系。

确认档案与成长成果快照的纯结构校验已位于 `shared/profile.js`，前端旧导入兼容保留。修改候选格式时须一起核对 schema、样例与共享实现；共享校验尚非完整 JSON Schema 引擎，也不能核实事实或自动识别所有语义补推。

**结构和引用合法不能证明内容属实。** 事实支持、敏感主题跳过、虚构成果、违反约束、语义重复与矛盾需要额外评测和内容规则，不能将当前格式检查称为完整事实验证。

格式修复即使未来接入，也必须保持候选状态，不能自动确认。事实缺口进入待澄清或删除相关提议；模型故障保留最近可靠输入，不跳过确认。

## 5. 用户确认

| 操作 | 行为 |
|---|---|
| 保留 | 接受当前条目及明确关联 |
| 修改 | 编辑该条目的主文本，保存为用户修改版本；当前未提供整套结构字段编辑或快捷原因 |
| 删除 | 从本次正式结果排除，显示撤销入口 |
| 撤销删除 | 回到待处理状态，不自动确认 |
| 返回改答 | 输入变化使旧确认与编辑失效，需要重新核对；删除决定继续保留 |
| 同输入重新整理 | 保留用户编辑文本和稳定 ID 对应的删除决定；仍逐条处理 |
| 继续 | 当前条目全部已确认、已修改或已删除后才进入结果；不隐式批量接受 |

删除经历后过滤依赖它的资本与河流关联。主张、方向和未知按各自确认状态处理，不能将其存在视为新增的确认证明。

当前删除追踪依赖稳定条目 ID；外部模型变换 ID 后的语义去重、冲突差异与重新分析优先保留用户修改仍待实现及验证。没有真实模型运行路径，不可据此宣称已完成上述保障。

## 6. 结果与地图提交

结果显示所有已确认对象，不固定为一个证明、一项人力资本或一条能力河。无保留判断时说明范围；未知为空不表示全部问题都已解决。

保存预览列出证明、定性关联、候选方向与未知项，不输出内部变更集编号或资本百分比。查看结果不等于保存；用户可选择：
- 仅本次使用：当前页面保留，刷新或离开后不继续保留。
- 保存到我的河：将确认对象写入当前浏览器，可在地图查看与删除，不代表账号或云端保存。

一次探索沿用同一会话，保存以本轮候选涉及对象为替换范围，删除项同步清除，其他探索保留；重复提交不增加重复记录。保存前读取最新档案，合并其他探索的独立变更；同条目被其他页面修改或删除时拒绝陈旧覆盖。损坏档案阻止覆盖，失败保留草稿与旧档案。

当前只更新文字、确认关系和证明入口。主河、支流形状、宽度与雾分布仍为视觉构图；新支流、增强变宽和局部雾散须有映射规则与独立验证后才实现。完成问卷不清空未知，不自动生成未来水道。

候选方向进入长期路径的规则见 [工作区规范](STAGE11_WORKSPACES.md)。

## 7. 保存与隐私

探索存储键为 `personal-moat:exploration-profile:v1`，与工作区和合成案例分开。用户主动保存的确认内容可能包含其自写行动、结果与来源；不能宣称保存后所有原始文本均不存在。

地图删除证明会清理其资本和河流关联；方向、未知和已建立长期路径是独立对象，删除证明不等于级联删除所有内容。真实模型接入前还需明确依赖依据失效后的重新评估流程。

不将原始回答、证明正文或链接、敏感属性或完整提示词写入分析日志。模型供应商、数据区域、保留期限和预算须在真实调用前明确。当前没有账号、跨设备同步、原子多标签事务或未保存草稿自动恢复。

## 8. 评测与下一步

现有合成回归覆盖结构、引用、确认过滤、文本安全、保存失败与部分冲突；证据见 [后续骨架报告](reports/next-foundation.md)。下一轮内容评测至少包含：

- 只有选项或少量自写也能完成；不编造结果或来源。
- 未问或跳过财务、身体主题时继续未知，不补推。
- 一经历多关联、多经历独立修改与删除。
- 只有偏好、相互矛盾输入、缺少跨情境验证。
- 删除或修正后重新分析、模型输出更换 ID。
- 模型不可用、超时、取消、非法输出及保存失败。
- 长期路径编辑优先，模型建议不能静默覆盖。

当前结构契约、本地案例测试与真实模型评测分别记录；内容题组、去重、模型与存储方案、强度映射、正式发布门槛均不能因骨架可运行而视为已完成。
