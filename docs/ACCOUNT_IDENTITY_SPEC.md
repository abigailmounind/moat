# 账号与匿名转账号规范

日期：2026-09-11。方向：托管身份服务 + 标准 OIDC。具体供应商尚未选择。

## 当前切片

已实现供应商无关的授权状态工具：state、nonce、PKCE verifier/challenge、过期校验，以及签名验证之后的 ID Token issuer、audience、nonce、subject 和时间声明校验。JWT 签名、JWKS 获取、授权端点和回调路由必须由选定供应商适配器实现，当前不进行外部请求。

## 登录边界

浏览器只保存短期授权事务引用，不保存 client secret 或完整 token。回调必须验证 state、nonce、PKCE 和 ID Token 签名，再从 provider 的稳定 `sub` 映射内部 account；邮箱、昵称等可变字段不能作为唯一身份。服务端主体从会话取得，前端不能指定 account 或 subject。

匿名会话与账号是不同主体。登录后发现本地或匿名数据时，先展示迁移预览（记录数量、路径、计划、成果证明和冲突），由用户确认导入。导入使用幂等键和版本检查，成功核对后再建立归属；不自动删除本地副本、不静默覆盖账号已有编辑。冲突保留两边内容并要求用户选择。

退出当前会话只撤销当前令牌；账号注销或删除数据另行确认。跨设备读取只返回当前账号主体数据，匿名旧会话不能继续访问已迁移的数据。会话过期、撤销、回调失败和迁移失败都保留可靠本地内容，并明确提示下一步。

## 供应商适配器待实现

1. 配置 issuer、client ID、redirect URI、授权端点和 JWKS 地址，启动时校验 HTTPS 与允许来源。
2. 生成授权 URL（authorization code + S256 PKCE），把事务存入服务端短期存储，限制单次使用和十分钟有效期。
3. 回调交换 code，验证签名密钥、iss、aud、nonce、exp、iat、sub；失败不创建或切换主体。
4. 建立账号主体、会话轮换和 CSRF 防护；账号会话与匿名会话不能共用令牌。
5. 实现匿名转账号的预览、确认、幂等导入、版本冲突、取消和失败恢复。
6. 在真实浏览器验证登录、回调、刷新、退出、跨设备和异常状态；供应商、费用、数据区域及保留期限确认后再接入。

当前纯函数测试不代表真实身份验证、JWT 签名验证、供应商可用性或用户验收。
