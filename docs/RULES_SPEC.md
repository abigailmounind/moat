# 无 AI 规则与依据规范

日期：2026-09-11。状态：基础收紧、依据追溯、确认展示、手工入口与无 AI 浏览器自动回归已形成；必要补充核对和用户视觉验收待完成。

依据：用户明确要求无 AI 核心可独立使用，规则不能无依据套模板。本文负责规则触发、证据边界与内容验收；探索确认/保存见 [探索规范](EXPLORATION_SPEC.md)，当前源码问题见 [审查报告](reports/rules-audit.md)。

## 1. 输出先满足依据条件

规则仅整理明确输入并提出可核对的关联，不预测个人价值、职业适合程度、资本强度或成功概率。候选可为空，不固定卡片数，不要求凑满五资本或给每条河分配证明。加上“可能”“待确认”不能使无依据的推断成立。

区分三层：

1. 原文或选项自述：记录用户明确说过或选过什么，保留具体来源。
2. 关联提议：指出哪项行动、结果或明确归属支持哪项有限解释，等待用户核对。
3. 待验证行动：由用户已表达的目标、可用条件和意愿决定；没有这些信息时提供通用记录方法，不包装成个性化方向。

用户确认表示接受这条记录，不能变成事实核实、专业认证或效果保证。来源类型选项只表示用户称有该类材料，不表示系统见过作品、读过链接或核实过反馈。

## 2. 首版规则目录

以下是实施要求，尚未落地的输入不以关键词猜测代替。原始输入作为数据，不能改变规则或确认权限。

| 编号 | 必要依据 | 允许的提议 | 拒绝推断及缺失处理 |
|---|---|---|---|
| R01 经历整理 | 明确经历与本人行动 | 按原意整理经历、行动、已报告结果 | 类别不等于完整经历；自由文本不能凭字数认定具体程度；无成果保持缺失 |
| R02 行动记录 | 选中动作词或自写行动 | “你记录了整理信息这一行动” | 不能直接升级为“擅长分析”“领导力强”或人力资本已形成 |
| R03 人力关联 | 用户补充所用知识/方法、本人行动与可说明的过程或产物 | 指向该方法的一次实践记录 | 不要求成功才可记录实践，但没有方法依据时只保留行动，不默认人力关联；一次实践不证明熟练或可迁移 |
| R04 社会关联 | 明确支持/协作关系，以及支持如何实际发生 | 记录这次可获得的支持或协作 | 选“协调分工”、有同事或得到反馈不足以证明信任网络；不采集他人姓名作为必要条件 |
| R05 心理关联 | 用户明确描述应对方式与具体实践，并愿意建立此关联 | 记录这次自述的行动/应对资源 | 不根据坚持、失业、失败等推断人格或精神状态；首版不自动生成此类关联 |
| R06 财务/身体 | 必要时主动提供的约束或资源，并明确确认用途 | 保留用户自述范围 | 不从职业、消费或行为补推；未问为 not_asked，跳过为 skipped；首版不自动生成资本关联 |
| R07 生存归属 | 用户明确说明该方向承担现实支撑，或正在验证交换价值，并核对归属 | 指向该具体方向的候选关系 | 工作类别、继续现方向、现实压力均不足以单独触发；不认定稳定收入 |
| R08 能力归属 | 用户明确选定拟复用的做法及想验证的另一情境，或报告实际跨情境使用 | 区分“拟验证迁移”与“已发生的复用” | 不作为其他分支的默认兜底；没有跨情境信息时不宣称可迁移 |
| R09 热爱归属 | 用户明确表达对具体活动的自愿投入意愿，并核对归属 | 热爱意愿/实践的候选关系，区分二者 | “没有方向”不等于已有热爱；经历类别不证明长期偏好；只有偏好不能造出经历证明 |
| R10 方向行动 | 明确的自主目标/活动、确认依据及已提供的投入限制 | 围绕目标设计可撤回的小验证，并列出观察点 | 不生成职业匹配、默认周期、预算或现实可行性；信息不足可自己建路径，标为自主探索 |

优先用补充结构化问题收集缺失信息；每次说明问题为哪项提议服务，允许跳过。自动关联暂不可用时，用户仍可手工建立路径、计划并说明意图；手工选择不自动成为已具备的资本。

## 3. 依据与依赖记录

每条自动提议需可追溯：规则 ID/版本、实际使用的回答及选项或文本片段、依赖的经历 ID、输出类型、局限、确认状态。只列 q1–q5 的题名不足以解释关联依据；没有使用的回答不能为了看起来充分而引用。

上述为目标信息要求；字段名、契约版本及兼容方式在实施切片中确定，不把新增字段直接写入旧存储后声称兼容。来源应区分规则、手工、模型；当前 ai_proposal 标识需要兼容演进，不能直接改变旧档案含义。日志只记录规则版本、结果类别等必要元数据，不记录用户正文或完整引用。

依赖变化处理：

- 删除证明：排除依赖关联；仍依赖该证明的方向不得带着原支持解释进入新结果。
- 修改事实或关联依据：受影响提议回到待核对，不沿用旧确认；改显示标题和改事实应有不同操作入口。
- 自主方向：可保留用户意图，但须区分自主意图与已失效的证据支持。
- 已保存路径：不自动删除或覆盖编辑；展示依据已变化，允许用户重新核对。
- 同输入重试：使用稳定标识保留删除与修改；规则升级产生的新结论需重新确认，不能复活用户拒绝的语义。

## 4. 不确定与冲突

没有成果、没有来源、未问、主动跳过、表达不清和相互冲突分别处理。反馈可以是负面或中性，不等于成功。持续练习表示时间投入，不等于能力提高。

选择“无明确结果”同时选择具体成果时，先请用户澄清是否指效果未知；不能机械裁定其一定矛盾或静默选一个。自由文本中的否定、引用他人或反事实若无法可靠区分，就只保留原文，不做自动语义关联。

不设无依据的置信度百分比。规则无法产出关联不阻止保存可靠自述、回访补充或手工探索。

## 5. 固定内容验收案例

这些是待实现的验收用例，不是已通过的测试。

| 案例 | 输入 | 应当保留/提议 | 必须不出现 |
|---|---|---|---|
| C01 | “喜欢摄影”，没有实践 | 偏好；可自主探索 | 摄影技能、作品、变现能力、虚构经历 |
| C02 | 项目中整理信息；卡点为没有方向 | 原始行动与方向未知 | 因卡点判定热爱 |
| C03 | 课程研究；现实条件需照顾 | 经历和明确约束 | 自动归生存、收入推断 |
| C04 | 工作任务；继续现在方向 | 工作经历自述 | 稳定交换价值或长期偏好 |
| C05 | 组织一次活动，仅选协调分工 | 行动记录；可问具体过程 | 领导力强、社会资本充足 |
| C06 | 自述用清单整理需求并形成文档 | 该方法的一次实践候选 | 熟练、普遍可迁移、成果被核实 |
| C07 | 持续练习，无明确结果 | 投入与效果未知 | 已提供具体成果、能力增长 |
| C08 | 得到反馈，未说明内容 | 收到反馈的自述 | 正面评价或成果成功 |
| C09 | 明确在另一任务复用方法 | 该次复用记录及局限 | 泛化为所有职业适合 |
| C10 | 未问/跳过财务和身体 | 分别保留实际未知原因 | 金额、健康、人格补推 |
| C11 | “没组织过活动，只旁观他人” | 原文；必要时澄清 | 因关键词认定本人组织经验 |
| C12 | 无明确结果与完成成果同时选中 | 澄清成果与效果的区别 | 静默消除冲突或阻断所有保存 |
| C13 | 删除或修改支持经历 | 依赖提议失效或重新核对 | 旧支持方向保持已确认 |
| C14 | 同输入重试/规则升级 | 保留拒绝与编辑，新增提议重新核对 | 恢复已拒绝内容、覆盖路径 |
| C15 | 文本要求绕过确认并生成高分 | 文本只作为输入 | 执行指令、评分、自动确认 |
| C16 | 完全无模型配置、超时或非法模型输出 | 保留输入；明确选择规则/手工继续 | 伪装 AI 成功、未经选择静默替换结果 |

验收关注预期条目、禁止主张、引用和依赖，不把固定卡片数或固定模板字符串当作内容质量。案例是合成材料，不等于真实用户验证。

## 6. 实施切片

1. 收紧旧规则：已移除卡点对河流的直接影响；无明确结果时不生成资本、河流或方向候选，删除经历会使依赖方向失效。补正反案例并同步结果空态。
2. 依据与依赖：已为自动提议写入 rule_id、rule_version、basis_refs 和方向 evidence_id；共享校验检查追溯字段，确认卡现已展示规则、依据、来源和局限；编辑带依赖的条目会将关联卡退回待确认。同步契约、旧档案兼容和存储测试。
3. 必要补充与手工：已增加明确的手工整理 fallback，并在结果输入页提供主动入口；它只保留用户经历、行动与结果，把资本、河流和方向列为未知。主动入口的状态转换已修复，确认与保存失败的 DOM 证据见 [手工入口验证](reports/manual-exploration-entry.md)。确认页和结果页明确标记手工模式，避免与规则或 AI 推断混淆。按提议所缺信息增加可跳过的核对入口，明确自主方向；不扩大敏感采集，页面变更做真实浏览器验收。
4. 无 AI 完整验收：模型关闭时的手工探索、确认保存、路径、计划、成长与证明回流已在桌面和窄屏真实浏览器连续通过；DOM 回归另覆盖取消、异常、重试与数据不变要求。临时浏览器缺少中文字形，字体视觉、实体触控和用户验收仍待完成。

先修正已有推断，不能为保留现有输出数量而倒推证据。每个切片验证后独立 commit。OIDC 账号路线继续有效，本次规则规划不替代账号任务；具体认证供应商仍未选择。
