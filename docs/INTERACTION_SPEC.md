# 交互规范 · 地图与跨页闭环

- 用途：状态、触发、退出、焦点与跨页协调。具体数据规则由探索和工作区规范维护。
- 最后更新：2026-09-10。以下区分当前实现与验收要求，状态见 [进度表](../milestones.md)。
- 页面、状态、投影与保存的代码职责见 [工程规范](ENGINEERING_STRUCTURE.md)。工程迁移应保留本文件的用户行为；DOM、HTTP 与浏览器验收按工程规范区分。

## 1. 信息层级与共用规则

**三河地图 → 人生节点 → 当前状态 → 下一步行动 → 导航与辅助信息。**

我的河、探索、未来路径、护城河计划和成长记录共用同一套左侧导航结构、图标、当前项高亮及底部入口；页面切换只改变当前项。

桌面详情位于地图右侧；窄屏使用地图下方的非模态详情区和三个中文河流入口。当前不采用强制焦点圈定的模态抽屉。地图与标签共用坐标，纹理不作为交互目标。

同一时刻保留一个主要详情层。临时 Hover 不覆盖已打开的证明或未来方向。数据提交、面板状态与动画分别管理；动画不是操作可用的前提。

## 2. 地图状态

| 状态 | 触发 | 展示 | 退出与焦点 |
|---|---|---|---|
| 默认 | 进入地图或重置 | 三河、个人记录入口和下一步；无记录时提供开始探索 | 可进入摘要、证明、方向或导航 |
| 河流摘要 | 指针或焦点进入河流、该河节点；点击河名固定摘要 | 对应主河与支流提亮，其他河节点减弱；展示该河的确认关联、资本类别、未知说明，以及已保存路径和有效归属计划 | 临时预览离开后收起；固定摘要可再次点河名、点空白或 Escape 收起 |
| 证明详情 | 点击节点或记录列表项 | 经历、贡献、成果、来源、确认状态、资本与河流解释及局限 | 打开聚焦标题；关闭归还有效触发器，必要时落回所属河流或本地记录入口 |
| 未来方向 | 操作河流或证明中的未来方向入口 | 所属河的候选、支持、缺口与下一步；无候选时说明空状态 | 关闭只改变视图，不删除记录；原三河、水道和构图不变 |

摘要内含可聚焦操作，指针或焦点进入摘要时保持可见。证明与未来方向互相替换；切换内容不叠加多层卡片。Escape 关闭当前层，不删除或离开页面。

## 3. 个人地图、演示与记录入口

默认 `/` 的摘要和证明来自当前浏览器保存的确认数据。个人地图的河面只投影路径空心圆与计划菱形，不再叠加证明圆点；证明通过河流摘要与地图文字说明查看，避免与工作区标记混淆。未关联任何河流的证明继续保留，不强行分河。

河流摘要分别显示该河的证明、路径和计划数量，只列出该河已保存的路径与有效归属计划，并可回到对应工作区详情。工作区记录不作为证明，也不改变资本或地图构图。

已保存路径和计划同时投影为所属河流上的地图节点：路径使用空心圆，计划使用菱形；悬停或键盘聚焦显示名称，操作后进入对应工作区详情。节点表达归属和入口，不表示资本增强或完成程度。

从某条河的入口打开证明应保留该河上下文。当前演示证明节点显式传入所属河；个人摘要的证明按钮尚未显式传入，跨河关联证明可能回到默认关联河。此项为源码核对发现的待修复边界，不能视为已全部实现；后续需补交互回归。

`?demo=1` 使用明确标记的合成地图案例；个人本地列表另有标记，不把合成经历写入个人档案。源码保留的构图宽度和雾分布不表示个人资本强弱。

删除证明需说明影响；成功后更新列表、数量并聚焦标题，不刷新整页。失败保留原记录并提示。成长成果可回看原记录；撤回其地图证明保留成长记录。详细删除语义见工作区规范。

## 4. 探索与长期路径衔接

探索输入、整理、逐条确认、结果和保存规则见 [探索规范](EXPLORATION_SPEC.md)，具体页面顺序见 [最短流程](STAGE10_MINIMUM_FLOW.md)。

卡片操作保持相对滚动位置与合理焦点；进入下一屏才聚焦新标题。取消、失败或返回不自动保存，不清空可靠输入。

保存候选方向后，可从地图进入路径草稿，核对后单独保存。已保存的同来源路径再次打开时显示已有编辑，不能重新带入提议覆盖用户文字。

## 5. 工作区交互

- 未来路径页按河流展开路径；护城河计划页继续展开路径下的计划，可保留多个路径分支展开。
- 从主导航进入路径或计划页时先显示概览。概览隐藏右侧详情或编辑区并扩展河流轴；进入时展开三条河，计划页同时展开全部路径，用户仍可分别收起。选择具体路径或计划后进入详情视图；携带具体对象的跨页入口可直接打开详情或编辑。
- 右上角“概览”进入时不保留节点选中态。已保存详情底部的“收起详情”以及“保存并查看概览”会保留当前节点选中，便于看清它在完整河流轴中的位置。
- 路径、计划和里程碑编辑表单可在保存成功后直接进入概览；校验或写入失败时继续保留编辑内容与错误提示。
- 新计划由路径创建或明确选择路径，默认使用当前路径或上次保存的河流；用户切换河流后只显示该河的路径，并须重新选择，保存结果仍保持路径与河流一致。
- 计划详情提供添加与编辑里程碑的独立表单。里程碑和行动分别记录完成，不能自动生成资本或成果。
- 成长记录按时间、河流、路径分组；分组仅改变视图。活动关系解除后可使用历史上下文。
- 展开河流或路径、切换记录分组保留表单输入。离开修改中的记录或新建另一条时处理未保存草稿。
- 保存失败保留草稿，完成勾选回到原值。刷新前未保存内容目前只有离开提醒，没有自动恢复。

字段、旧数据兼容、保存与删除依赖集中见 [工作区规范](STAGE11_WORKSPACES.md)，不在本文件复制。

## 6. 可访问性与待验证设计

键盘、触控和减少动态效果应能完成同一闭环；控件有可读名称、焦点样式与明确状态，不依赖颜色或 Hover。触控目标优先至少 44 × 44 CSS 像素，避免重叠。长内容允许自然滚动。

普通证明、重要经历、人生里程碑可采用不同视觉层级，表达信息重要性而非人的价值。完整三层符号、聚合与缩放阈值尚未实现，不要求凭空补满地图。

验收覆盖三河层级、详情互斥、焦点归还、空态、失败与删除、快速切换、窄屏和长文本。自动检查与浏览器限制按 [文档导航的验证证据](README.md#验证证据与历史入口) 查阅；DOM 检查不等于实际布局或用户视觉验收。
