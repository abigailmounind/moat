# 工程结构与开发规范

- 用途：工程目录、模块职责、依赖边界、编码约定、数据修改与验证要求的统一入口。
- 版本：V0.2；更新于 2026-09-10，按现有源码核对整理。
- 阅读顺序：[协作规则](../AGENTS.md) → [PRD](../PRD.md) → [当前进度](../milestones.md) → 本文 → 任务专题。运行命令见 [项目 README](../README.md)，文档职责与同步矩阵见 [文档导航](README.md)。

## 1. 技术基线与适用范围

当前应用使用原生 JavaScript ES Modules、DOM、SVG、CSS 和 Node HTTP 服务，没有构建框架或打包器；服务端新增 `pg` 数据库驱动及锁文件。Node 运行要求见 README。沿用现有模块，新增功能按职责拆分；数据库驱动用于已授权的持久化切片；不因目录整理引入 React、动效库或云服务。

下文“当前结构”描述已存在的文件与行为，“开发规范”约束后续修改，“待收口”明确尚未满足的目标。结构规范不替代产品决定；完成状态只在 milestones 维护。数据库、认证、模型与部署选择的权限沿用 AGENTS，本文不追加授权。

这是当前目录，不是未来目录占位清单。数据库迁移已建立；身份供应商与后台任务模块尚未建立；新增时说明职责、依赖、验证与配置，再更新此处。根目录旧 `src/` 和旧 `index.html` 已迁出，不能恢复为第二套实现入口。

`frontend/` 负责浏览器环境；`backend/` 负责服务环境；`shared/` 只放跨环境纯数据逻辑；`contracts/` 存储交换格式与样例。新增模块先判断它依赖哪种环境、承担哪项职责，避免以 `utils` 聚集不相关的规则。

## 3. 启动、页面与模块定位

### 启动与公共文件

`npm start` → `scripts/serve.mjs` → `backend/server.mjs`；`/` 映射 `frontend/index.html`，由 `frontend/src/main.js` 依据 `view` 动态加载页面。URL 与实际目录不必相同，页面路由完整列表见 README。

静态服务使用明确白名单，不公开整个仓库。五个共享模块是浏览器需要的公共源码；`backend/`、项目文档和非白名单路径不会因存放在仓库而自动可访问。现有 `frontend/src/` 文件名模式内的新 JS/CSS 可直接对外提供，新增目录或共享文件则需核对白名单。修改公共模块路径时同时核对 import、静态白名单、类型和 HTTP 检查。禁止将密钥、用户数据或服务内部配置放到公共路径。

|---|---|---|

| `backend/product-service.mjs` | 方法、来源、JSON、会话、错误响应，等待仓储结果 | 不直接访问浏览器存储，不复制仓储状态 |
| `backend/product-repository.mjs` | 主体隔离、结构复核、版本比较、写入和幂等回执 | 当前没有数据库、账号和跨进程事务 |

| `shared/profile.js` | 确认档案及成果快照的结构与引用校验 | 不判断自述真实性、不推断资本强度 |
| `shared/workspace.js` | 工作区结构、历史兼容、日期与基本引用 | 不等同于每项新增、移河、删除操作的完整业务授权 |

## 4. 依赖规则与现存例外

常规依赖方向：

- 前端页面 → 本地状态、渲染、存储或客户端模块 → `shared/`。
- 服务入口 → 请求服务 → 仓储；产品服务、仓储可使用 `shared/`。
- `shared/` 可依赖其他共享模块和跨环境标准语言能力，不能依赖 DOM、浏览器存储、Node 专用模块、`frontend/` 或 `backend/`。
- 前端不能 import `backend/`；与服务端交互使用 HTTP 契约。测试和检查脚本可以从被验证模块导入纯函数。

候选校验已统一到 `shared/understanding.js`；前端保留原导出，分析服务与 CLI 直接引用共享层。CLI 保留错误数组返回接口，错误内容统一为共享校验结果；尚未使用通用 JSON Schema 引擎。

当前例外必须保持可见：

| 例外 | 当前依据 | 收口条件 |
|---|---|---|
| 前端领域与本地存储尚未完全拆开 | workspace-model 保留本地提交与兼容导出，移河/删除已抽入 shared；exploration-domain 经 review 依赖渲染工具 | 按具体任务拆分，纯规则才进入 shared；保持调用与存储兼容 |
| 地图导航及构图数据仍有共享依赖 | app 内导航与 sidebar 并存；个人投影、state 仍使用 data 的构图或默认信息 | 修改时回归个人空态与演示隔离，不把同文件依赖误称为数据混用 |

禁止扩大这些例外来复制校验或让服务读取 DOM。例外的处理优先级见 milestones；列出例外不表示本轮已经重构。

## 5. 数据流、校验与保存边界

### 当前两条独立数据路径

浏览器闭环：回答 → 本地规则候选 → 逐条确认 → 确认档案的本地提交；路径/计划/成长记录由工作区本地提交保存。地图读取探索档案与成果快照形成视图。

开发态 API：HTTP 请求 → 服务端匿名会话 → 聚合结构校验或路径/计划对象操作校验 → 内存原子提交或 PostgreSQL 事务提交。它与浏览器档案尚无自动同步、导入或共同身份；前端打开页面不会因此变成服务端保存。

| 数据层 | 当前位置 | 版本与生命周期 |
|---|---|---|
| 探索回答、确认前编辑、页面草稿 | 当前页面内存 | 离开或刷新可能丢失；未自动恢复 |
| 确认探索档案 | `localStorage` 的探索专用键 | 信封版本及对象/变更集校验；精确键见探索规范 |
| 路径、计划、里程碑、成长和快照 | `localStorage` 的工作区专用键 | 工作区 version 与 revision；精确键及删除语义见工作区规范 |
| 地图入场偏好 | `sessionStorage` | 展示偏好，不作身份或业务状态 |
| 匿名主体、空档案、工作区、回执 | 内存或 PostgreSQL 仓储 | 聚合 revision；内存重启清空，PostgreSQL 持久化，参数见 API 契约 |
| 合成示例 | `data.js`、contracts 样例、测试夹具 | 不冒充个人记录，不用于填满个人空态 |

`contract_version`、本地存储 `version` 和工作区 `revision` 分别承担交换格式、存储格式和并发版本职责，不能互相替代。修改字段时同时考虑旧档案、候选校验、快照与 API 的兼容性。

共享结构校验为基础检查。移河、删除及历史上下文已抽入共享操作层；路径/计划对象接口在仓储原子边界内调用这些规则并校验归属。聚合 PUT 仍保留旧数据兼容，不能当作生产环境的任意导入或完整操作授权入口；前端迁移前需继续收口聚合写入范围。

服务器连接层用 Web Locks 串行化跨标签连接操作。无锁或申请失败返回 lock_unavailable，不触发网络和连接缓存变更；纯本地读写沿用原行为。该限制保护待提交记录，不能用单页面 Promise 队列声称实现跨标签互斥。

连接层通过 WeakMap 标记 readActive 返回快照及保存结果的来源（本地或服务器主体）；保存/删除/确认/撤回前复核来源，服务器提交在锁内再次复核。页面应传回连接层原快照作为 base，编辑副本仅作为 item；复制 base 会丢失内存来源标记。这是客户端防误存保护，不替代服务端权限与版本检查。

### 修改数据的通用要求

纯转换返回新数据，读取和响应使用隔离快照；渲染与投影不偷偷保存。明确区分草稿、候选、已确认对象和提交结果；成功反馈以实际写入成功为准。错误、取消、损坏版本和陈旧提交保留可靠数据及可保留的输入。

服务端从会话取得主体，版本检查、关联修改和成功回执必须位于同一原子边界。内存适配器使用单进程同步边界；PostgreSQL 使用工作区行锁、同事务回执及固定快照读取，真实数据库验证见本轮报告。HTTP 字段、幂等窗口及错误码只在 [API 契约](PRODUCT_API.md) 维护。

用户数据、证明正文、链接和完整提示词不进入产品分析日志；使用合成夹具测试。模型、规则和手工方式最终都应经过用户确认及确定性提交；当前本地规则的局限见探索规范。

## 6. 编码与模块约定

| 方面 | 开发约定 |
|---|---|
| 文件与命名 | 浏览器和 shared 使用 `.js`，Node 模块与测试使用 `.mjs`；普通模块沿用小写连字符，导入写完整扩展名；文档遵循现有命名，不为统一名字破坏链接 |
| 职责与副作用 | DOM 访问放页面/渲染层，存储放适配层；shared 导入不创建会话、不写存储、不注册页面事件 |
| 函数接口 | 导出与参数说明它处理何种对象；保留稳定 ID 和来源状态；修改兼容导出前检查全部调用方 |
| 可测试依赖 | 服务通过参数注入仓储、供应商等；需要测试时间、ID 或失败时沿用现有注入方式，避免在纯规则内硬绑环境 |
| 异步工作 | 等待提交结果；超时、取消、失败和资源释放成对处理；不能把 Promise 当已保存结果 |
| 错误与文案 | V1 使用统一错误对象，旧分析接口保留其兼容格式；用户文案简明中文，内部原因不包含隐私正文 |
| 渲染与输入 | 用户文本转义后显示；用户数据不能成为 HTML、URL 权限依据或执行规则；来源链接按明确允许的行为处理 |
| 样式与资产 | 复用现有 CSS 与资产；修改前核对最终覆盖规则；源、派生文件和运行引用一起核对，细则只在资产索引维护 |
| 改动粒度 | 保留用户工作区修改；新代码按清楚的逻辑块书写，注释解释边界与理由；不夹带全仓格式化或无关依赖升级 |

当前没有 formatter、lint 或构建检查配置。现有 `scripts/check.mjs` 会递归使用 Node `--check` 解析 frontend/src 与 shared 的 JavaScript 模块，覆盖动态加载页面的语法与重复导入绑定；不执行模块，不验证导出链接或浏览器运行行为。不能把以上全部约定说成已由工具强制。新增工具及依赖应说明具体收益和影响，在已有任务授权内执行。

## 7. 验证与交接要求

`check-postgres.mjs` 调用 `tests/fixtures/postgres-lifecycle-check.mjs`，在隔离 schema 中注入真实 SQL 失败并协调写入/删除顺序，检查数据、版本、会话和回执的一致性；同时覆盖 HTTP 成长证明、导出删除及服务重启。证据见 [生命周期验证](reports/postgres-lifecycle.md)。

Pages 静态发布由 `scripts/build-pages.mjs` 在测试和静态检查通过后生成独立临时目录；`scripts/check-pages.mjs` 验证线上页面、模块语法与资源响应。部署流程及本轮证据见 [Pages 成长页发布](reports/pages-growth-release.md)。这些检查不替代真实浏览器行为与视觉验收。

`scripts/browser-flow-check.mjs` 使用外置 Playwright 与 Chromium，连续验证无 AI 本地闭环的桌面和窄屏浏览器行为；依赖和浏览器不进入生产依赖。运行参数见根 README，本轮证据见 [手工探索入口验证](reports/manual-exploration-entry.md)。触控模拟和无横向溢出检查不替代实体设备或字体视觉验收。

| 改动 | 必需关注的证据 | 不足以证明 |
|---|---|---|
| 领域、确认、存储与版本 | 正常、非法输入、失败及关键边界回归 | 格式合法不等于事实核实 |
| API 或仓储 | 未授权、来源、主体隔离、版本、重试与失败；路由或静态模块变更加真实 HTTP 检查 | 内存/异步包装不等于数据库事务与重启恢复 |
| 页面交互 | 对应 DOM 行为回归；布局变更加真实浏览器检查 | jsdom 不验证布局、触控或视觉 |
| 地图、样式、动效 | 三河层级、窄屏、键盘、触控、长文本及减少动态效果 | 资源能加载不等于用户接受视觉 |
| 资产派生 | 来源、派生关系、运行引用及必要视觉复核 | 文件导出成功不等于设计验收 |
| 纯文档 | 实现依据、相对路径、链接、现行规则与历史一致性、差异 | 不沿用旧测试结果声称本轮重新通过 |

具体命令统一查 README。测试关注用户可观察行为及风险，不为简单文档改动运行无关测试。检查通过后，如无新改动或未解决风险，不重复执行。

交接说明实际改动、证据、未验证部分及下一步；报告记录日期和范围，当前状态回写 milestones。提交、发布或外部接入的授权按 AGENTS 处理。

## 8. 工程变更怎样同步文档

先更新规则的主文档，再按 [文档同步矩阵](README.md#文档同步矩阵) 检查受影响入口。目录、依赖与模块职责变更更新本文；命令和配置更新根 README；HTTP/仓储字段更新 PRODUCT_API；数据操作语义更新探索或工作区规范；里程碑完成边界只更新 milestones。

新增模块必须能从本文或相应专题定位；新增专题必须进入 docs/README.md。历史报告中的路径和检查结论保留当时语境，由导航链接到当前规范，不能批量改写历史证据。
