- 用途：记录已确认的产品语义、设计约束与理由，防止后续实现回退到不适用的范式。
- 状态：V0.1；当前 source of truth 范围为下列产品与设计决策。未定义完整 PRD、评分算法或数据模型。
- 最后更新：2026-09-10（整理现有决策，不新增产品决定）

工程目录、依赖与开发约定见 [工程规范](ENGINEERING_STRUCTURE.md)；后端方案与当前接口分别见 [后端架构](BACKEND_ARCHITECTURE.md)、[API 契约](PRODUCT_API.md)。这些工程文档不替代本表的用户决定，也不把数据库或供应商建议升级为已确认选择。

## 1. 三条主河的语义

| 当前名称 | 产品语义 | 设计与解释要求 |
|---|---|---|
| 生存之河 | 当下赖以生存、正在形成稳定交换价值的方向 | 解释现有生存支撑与实际经历，避免将收入直接等同于人生价值 |
| 能力之河 | 脱离当前岗位后仍可迁移、复用并支持生存的能力 | 展示跨岗位可用的能力及证据，避免只复述职位名称 |
| 热爱之河 | 抛开生存顾虑后真正愿意投入的事情与方向 | 允许开放探索、证据不足和未来可能，避免把暂时兴趣直接定为终身方向 |

采用三河可以同时呈现现实支撑、可迁移能力与内在意愿，保留彼此联系及差异。三条主河从中央自然交汇区域向外延伸，各有支流；禁止第四条平级主河。当前名称供后续统一使用，不另造一组相近名称。

## 2. 关键决策与 rationale

| 编号 | 已确认决策 | 理由与执行边界 |
|---|---|---|
| D01 | 五资本 = 支流 | 人力、社会、心理、财务、身体资本为人生方向提供支撑。支流体现贡献关系，分类可通过小符号和标签识别。五类资本不扩张成五条主河，也不强制使用五种鲜艳颜色。 |
| D02 | 支流粗细表达支撑强弱 | 宽度对应某资本对该人生方向的实际支撑程度。避免同时编码 AI 置信度、偏好或职业匹配度；宽度计算与阈值尚未确定。 |
| D03 | 证明节点 = 真实证据 | 项目、作品、经历、成果与事件让结论有出处。节点应说明发生了什么、用户做了什么、支持哪项资本或方向。示例经历不能成为真实用户记录。 |
| D04 | 地图结论尽量由证据支撑 | 从证据到资本再到河流结论应能解释。仅凭一句自我评价，不应直接加强水系；证据不足时保留探索状态，说明仍需补充的信息。用户自述、作品记录与已核实信息应如实呈现来源，不能默认全部经过验证。 |
| D05 | 雾 = 未知 / 未探索 | 雾可能来自尚未探索、证据不足、方向未稳定或未来开放性。它不等于弱、失败、坏或风险；雾色明亮柔和，不使用惩罚式文案。 |
| D06 | 未来方向使用信息层表达，不生成地图分叉水道 | 未来方向仍说明已有支持、缺口与验证行动，并可保存和修改；“我的河”保持稳定的三河视觉，不因方向新增或编辑生成矢量分叉。可在未来单独验证轻量引导线与文字，但未经视觉验收不进入正式地图。避免职业匹配百分比、命中率排名与机械推荐卡片榜。 |
| D07 | 主河本体保持统一水系语言 | 统一低饱和青蓝水体使地图属于同一视觉世界；通过地形、标签、节点和状态区分三河，避免把水体变成分类图表。 |
| D08 | 轻游戏化只服务探索感 | 雾散、支流生长、节点出现提供发现和积累的反馈。避免角色等级、战斗、装备、任务奖励与奇幻 RPG 景观。 |
| D09 | 设计系统避免 Dashboard 化 | 地图承载主要理解与交互。统计和行动为辅，避免 KPI 卡片墙、饼图、雷达图或仪表盘重新主导结果。 |
| D10 | 地图是长期动态个人空间 | 用户每次补充信息都能回到同一张地图，理解新增与变化。稳定的河道身份、证据关联和当前状态支持长期积累。 |
| D11 | 未来路径与护城河计划是长期工作区 | 未来路径按三条河组织，支持保存、比较、补证据与反复编辑；每条路径可展开多个护城河计划，新计划只属于一条路径并继承其河流，承接资本目标、行动和里程碑。计划编辑时可先改河流，再从该河重新选择路径，保存结果仍须保持归属一致。不能做成平级列表或看完即结束的静态输出。 |
| D12 | 结果拆为多个聚焦页面 / 屏幕 | 分步帮助用户理解发现、证据、地图变化和行动，降低阅读负担。避免一篇超长报告；具体屏幕数量与划分仍需设计。 |
| D13 | 后续命名优先中文 | 产品模块、页面、流程、原型与 PRD 使用一致的中文名称。必要时首次括注英文，减少在不同阶段反复切换术语。 |
| D14 | 地图更新必须经过独立确认与确定性提交 | AI 只提出带来源的理解和变化建议；用户查看结果不等于同意更新或长期保存。确认后的变更通过系统校验并提交，失败保持原地图，避免模型直接改写个人档案。 |
| D15 | 探索信息按来源与确认状态分层 | 原始回答、用户自述、AI 提议、用户确认版本与证明来源分别保存语义；跳过保持未知，删除的推断不得被重新分析自动恢复。这样能让结论可追溯、可修改，也避免把自述冒充独立核实事实。 |
| D16 | 三河主图静态页面是全产品视觉母体 | 探索、结果和长期工作区共享主图的背景、纸感、地形、等高线、柔雾与低饱和色彩气质；页面任务可以改变布局和元素密度。由此保持产品世界连续，同时避免复制完整地图妨碍阅读或表单操作。后续未验收细节不自动成为全局规则。 |

## 3. 关键修订依据

| 来源与先后关系 | 当前采用 | 影响 |
|---|---|---|
| 2026-09-09 用户拒绝未来分叉的视觉表现，随后接受阶段 9 妥协版本 | D06：未来方向仅在详情与工作区呈现；取消额外常驻动态流纹 | 不依据旧稿恢复分叉水道，水面保留源资产静态纹理 |
| 阶段 11 用户反馈并确认：路径位于三河下，计划位于路径下，计划河流随路径 | D11：新计划单路径归属，增加里程碑建立入口与成长记录分组 | 旧同河多路径保留是兼容实现，不代表重新开放新建多路径计划 |
| 用户授权暂不能逐步验收时继续搭后续骨架 | 按 D10、D14、D15 实现个人地图、动态确认与方向到路径的单独保存 | 授权实施不等于视觉通过、选择供应商或授权发布 |

## 4. 目标与实现区分

D02、D05、D08 描述支撑、未知和探索反馈的产品语义。当前宽度、支流和雾分布沿用构图，没有资本评分或个人强度映射；不把这些决策写成已实现算法。

AI 提议、用户确认、系统执行是目标闭环；当前候选来自本地规则，模型接口默认关闭。格式与引用检查不能验证事实，也不能证明真实模型不会覆盖用户编辑。

模型供应商、云端身份与存储、语义去重、强度映射、正式设计 token 和发布门槛仍待明确。后续计划见 milestones，不通过追加模糊“建议”改变本表。
