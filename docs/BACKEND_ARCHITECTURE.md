# 后端与无 AI 运行架构

- 用途：定义从本地前端原型走向完整产品时的服务端职责、数据边界、AI 降级方式与实施顺序。
- 状态：V0.3；2026-09-12 已加入阿里云百炼新加坡 Free-only 多模型适配骨架。本地 PostgreSQL 实现保留；认证服务与正式部署仍未选择。
- 关联：[PRD](../PRD.md) · [探索规范](EXPLORATION_SPEC.md) · [工作区规范](STAGE11_WORKSPACES.md) · [阶段进度](../milestones.md)
- 工程定位：目录、依赖、现存例外与编码约定见 [工程规范](ENGINEERING_STRUCTURE.md)；当前可调用接口与仓储细节见 [API 契约](PRODUCT_API.md)。本文维护服务端目标与迁移边界，实施状态由阶段进度维护。

## 1. 当前事实与目标

当前 Node 服务提供静态文件、旧分析兼容接口，以及一组开发态产品 API：服务端可签发匿名会话，按会话返回启动数据，用内存或 PostgreSQL 仓储读写工作区，并运行确定性规则分析、按确认变更集持久化探索档案。前端默认仍把探索档案、路径、计划、里程碑与成长记录保存在浏览器 `localStorage`；内存仓储重启即清空；PostgreSQL 已能恢复匿名会话、档案、工作区和回执，相关迁移、事务、并发和 HTTP 重启专项已在隔离测试库通过。浏览器同步、注册身份、跨设备恢复、完整导出删除与审计仍需继续建设。

目标采用一个可逐步扩展的模块化单体后端，不在 MVP 阶段拆微服务：

```text
浏览器界面
  ├─ 本地草稿与离线缓冲
  └─ 产品 API
       ├─ 身份与会话
       ├─ 个人档案 / 工作区 / 成长记录
       ├─ 确认、版本冲突、导出与删除
       └─ 分析编排
            ├─ AI 模型适配器（可选）
            ├─ 确定性规则整理（默认可用）
            └─ 手工录入与确认（始终可用）
                 ↓
         持久化数据库 + 必要的后台任务
```

首版继续使用现有原生 JavaScript 前端和 Node 服务。后端先保持同仓库、同域 API，降低认证、跨域和部署复杂度；有明确容量或组织边界后再考虑拆分。

## 2. AI 不是核心闭环的单点依赖

完整流程为：**输入或记录 → 候选整理 → 用户确认 → 确定性校验 → 服务端提交**。模型不能直接写个人档案。当前浏览器闭环默认以本地规则和本地提交结束；页面已在能力确认与本轮显式同意后连接可选模型分析，确认档案也可通过独立同步入口连接服务端。

| 模式 | 触发 | 用户仍可完成 | 产品必须说明 |
|---|---|---|---|
| 模型辅助 | 供应商已配置且调用成功 | 获得更自然的经历拆分、关联解释和方向建议，再逐条确认 | 内容为 AI 提议，尚未核实或保存 |
| 规则整理 | 未配置模型、超时、限流或模型输出无效 | 用确定性规则整理已有选项和明确自述，生成克制的候选；继续确认、保存和建计划 | 当前使用本地规则，结论范围更窄 |
| 手工模式 | 输入不足、规则也不能安全形成关联，或用户主动选择 | 直接添加证明、选择河流/资本、建立路径、计划、里程碑和成长记录 | 没有自动推断；未知继续保留 |

模型失败不能显示虚假成功，也不能静默换成看似由 AI 得出的完整分析。若降级到规则模式，应保留输入并明确标记来源；若连规则候选都没有足够依据，应进入手工模式，而不是补写经历或结论。

模型恢复后可以提出新的候选版本，但不得覆盖用户已编辑的路径、计划、证明和确认文本。重分析必须形成可比较的差异，由用户决定是否采用。

## 3. 服务端职责

本节描述持久化与正式服务需要承担的职责。当前已有开发态匿名会话、聚合工作区及 PostgreSQL 路径/计划对象切片；对象级版本、完整时间戳、确认提交、账号与删除任务不能据本节视为已实现。

### 身份与访问隔离

- 首次匿名使用由服务端签发不可读的安全会话标识；不把用户 ID 当作前端可任意指定的权限依据。
- 注册或登录后，用户明确选择是否把本地/匿名内容合并到账号；迁移先写入并校验成功，再标记本地副本已同步，不自动删除原数据。
- 每次读写都由服务端从会话得到主体，并校验对象归属。管理员或分析日志不能绕过产品数据隔离。
- Web 会话优先使用 `HttpOnly`、`Secure`、`SameSite` Cookie；具体认证供应商在实施前确认。

### 产品数据

服务端按产品语义保存下列对象及其版本：

- 用户/匿名主体、档案与同意记录；
- 探索会话、原始回答的临时状态、分析候选与逐条确认；
- 证明、资本关联、河流关联、未知项和候选方向；
- 未来路径、护城河计划、里程碑、行动和成长记录；
- 成果证明快照、来源关系及必要的变更原因。

确认后的产品对象使用明确字段和关联；模型原始输出只作为待确认候选，不直接成为正式档案。自由文本、敏感回答和证明链接不进入产品分析日志。

### 一致性与恢复

- 所有可编辑对象带稳定 ID、`revision`、创建/更新时间及来源状态。
- 写接口要求当前版本或 `If-Match`，用数据库事务处理关联更新，冲突返回可理解的 `409`，不采用最后写入者静默覆盖。
- 创建操作支持幂等键，网络重试不重复建立路径、计划或证明。当前聚合工作区 PUT 已支持可选幂等键；同键同内容重放首次响应，同键异内容返回 409，具体窗口与事务要求见 [产品 API 契约](PRODUCT_API.md)。
- 删除先明确影响；用户数据删除、账号删除、备份到期删除和导出分别定义，不把页面隐藏当作删除完成。
- 服务端失败时保留浏览器草稿；同步成功前不清除可靠的本地数据。

### AI 网关

- 模型密钥、供应商调用、超时、限流、成本与输出校验只在服务端。
- 只发送完成当前分析所需且用户已同意的字段，不默认发送整个个人档案。
- 每次候选记录分析模式、契约版本、模型/规则版本、耗时和结果状态；日志不记录完整提示词与用户正文。
- 供应商调用失败后进入规则或手工模式；重试不能产生重复正式记录。

## 4. API 边界 V1

以下区分当前接口与规划接口。现有字段、状态码、回执窗口和限制以 [API 契约](PRODUCT_API.md) 为准：

| 领域 | 接口 | 实现范围 |
|---|---|---|
| 系统 | `GET /api/v1/capabilities`、`GET /api/v1/health` | 当前可调用；规则/手工能力枚举不代表已有服务端分析端点 |
| 会话 | `POST /api/v1/session`、`GET /api/v1/session`、`DELETE /api/v1/session` | 当前匿名会话与当前令牌撤销；PostgreSQL 有固定服务端有效期，无注册账号、续期或回收任务 |
| 启动数据 | `GET /api/v1/bootstrap` | 当前返回主体、确认档案及独立档案 revision、工作区 |
| 工作区聚合 | `GET/PUT /api/v1/workspace` | 当前可调用；结构、会话、版本与幂等检查，不等于完整操作级规则 |
| 对象级工作区 | `/api/v1/paths`、`/api/v1/plans` | 已实现创建、完整更新、删除、读取及归属规则，工作区级版本；成长记录、证明独立确认/撤回及空工作区导入已实现，持久库专项已通过，见 [生命周期验证](reports/postgres-lifecycle.md) |
| 探索分析 | `POST /api/v1/analyses/rules`、`POST /api/v1/analyses/model` | 规则模式与可选百炼后台路由；模型失败明确回退规则，只返回待确认候选，不保存原始回答 |
| 确认提交 | `GET /api/v1/profile`、`POST /api/v1/profile/change-sets` | 当前按独立档案 revision 和确认变更集写入；模型候选与页面自动同步仍未接入 |
| 个人数据 | `POST /api/v1/imports/workspace`、`GET /api/v1/data/export`、`DELETE /api/v1/data` | 工作区导入与当前匿名主体服务端导出/删除已实现；浏览器副本、备份清理、账号注销仍待建设 |

当前 `/api/analysis` 与 `/api/capabilities` 是原型接口，固定不接真实供应商，仍使用旧错误格式。V1 模型端点仅在新加坡普通 Key、模型白名单及 Free Quota Only 人工确认同时具备时启用；页面只在能力可用且用户本轮主动同意外部处理后调用。V1 两类分析共享规则输入和候选校验，确认档案写入复用 `shared/profile-changes.js`；页面默认本地保存，连接流程显式说明外部处理、复制或切换及冲突处理。

## 5. 持久化建议

生产环境优先使用支持事务、约束和备份恢复的关系型数据库。当前数据具有清楚的所有权、层级和关联，关系型结构比把全部内容保存为单个 JSON 更适合处理归属、删除影响、并发更新与查询。

已采用 PostgreSQL 作为当前本地及参考持久化实现；Cloudflare Workers + D1 免费方案已建立独立入口、版本化迁移、档案/工作区一致读取、事务幂等写入、条件主体级联删除、规则整理及默认关闭的百炼模型网关。公开请求经过边缘桶；模型全局日名额、个人小时计数和在途锁由 D1 原子保护，删除个人数据不会重置全局限额。模拟与真实本地 D1 专项见 [发布保护验证](reports/cloudflare-release-guards.md)。Pages 同源适配器与可选 API 打包已完成真实本地服务绑定联调，见 [同源接入验证](reports/pages-api-integration.md)；隔离 D1/Pages 已完成远程与浏览器验证，见 [预发布验证](reports/cloudflare-staging-release.md)；隔离环境随后按用户确认接入 Free-only 模型，真实通道与已知限制见 [AI 与计划入口修复](reports/staging-ai-plan-entry.md)。账号与备份恢复仍待完成。两套实现并存并沿用 `/api/v1` 语义，不删除 Node + PostgreSQL。本地开发可使用独立测试库或同一仓储接口的内存适配器。不要把本地 JSON 文件当作生产持久化，也不要让浏览器 `localStorage` 成为账号数据的唯一事实来源。

当前首批迁移包含主体、会话、空档案、档案版本、确认回执、工作区版本、路径、计划、归属、成长记录与工作区回执。里程碑、行动和证明快照暂随对象 JSONB 保存；探索原始回答和候选不落库，确认档案仍以受控 JSONB 保存。附件或大文件后续进入对象存储，数据库只保存受控元数据与归属；MVP 不因尚未实现附件上传而阻塞文字和链接证明。

Cloudflare 访客统计使用独立 `visitor_events` 表，与主体、会话、档案和工作区无关联。写入不保存 IP、Cookie 或主体标识；位置来自 Worker 请求的 `request.cf`，国家值按代码保存，合法经纬度在写入前四舍五入至 0.1 度。明细仅由持 `VISITOR_STATS_ADMIN_KEY` 的管理请求读取，密钥只存 Worker Secret。

## 6. 前端迁移方式

当前已提供数据与同步入口：工作区和探索确认档案分别预览，明确确认后连接或复制到对应的空服务器数据集，原本地数据保留且不自动合并；探索连接不上传原始回答。以下完整账号迁移与恢复步骤仍是目标。

1. 保留当前 `localStorage` 读取能力，先增加 API 客户端和能力探测。
2. 未登录时可继续本地使用；有服务会话时将已确认数据写到服务端，页面以服务端版本为事实来源，本地只保留草稿和短期缓存。
3. 首次登录发现本地数据时展示迁移预览；用户确认后执行幂等导入，成功后核对数量与版本。
4. 服务不可达时允许继续编辑本地草稿，并显示“尚未同步”；恢复后按对象版本提交，冲突由用户选择，不自动覆盖。
5. 全链路验证完成后再缩减旧存储职责；不得一次性清空用户已有浏览器内容。

## 7. 实施切片与验收

### A. 后端地基

- 冻结 API 错误格式、能力模式、对象版本和幂等规则。
- 建立领域服务与仓储接口，使用内存适配器完成单元测试。
- 补系统健康、匿名会话、工作区读写、版本冲突及访问隔离测试。

通过标准：不接数据库或模型也能验证结构、版本、重试、访问隔离与失败；共享校验不依赖页面。地基阶段证据见 [后端地基第二轮](reports/backend-foundation-v2.md)；后续 PostgreSQL 路径/计划切片已验证事务与重启恢复，见 [首轮持久化报告](reports/backend-persistence-v1.md)。完整会话生命周期与账号继续建设，阶段范围统一见 milestones。

### B. 服务端持久化纵向切片

- 已采用 PostgreSQL 与版本化 SQL 迁移，先打通路径 → 计划 → 里程碑 → 成长记录 → 证明快照。
- 覆盖事务、冲突、重复请求、保存失败、导出和删除。

首轮已验证服务端路径/计划读写、事务、幂等、归属与 Node 重启恢复；前端接入、显式迁移和成长记录独立接口已有代码，真实浏览器迁移闭环仍待验证；成长、证明、导入与导出删除已通过持久库专项及 HTTP 重启检查，见 [生命周期验证](reports/postgres-lifecycle.md)。换浏览器登录恢复尚未实现。完整通过标准仍包括这些后续步骤。

### C. 探索与 AI 双通道

- 把现有结构契约接入服务端规则模式，再增加可替换的模型适配器；当前规则候选和确认变更集已接入共享校验与仓储事务。
- 固定内容评测覆盖信息不足、偏好、多经历、矛盾、删除修改、敏感跳过和模型故障。

通过标准：模型关闭和故障时核心闭环可完成；模型开启时仍经过相同确认、校验与提交路径。

### D. 账号、迁移与发布准备

- 实现登录、匿名转账号、本地导入、跨设备同步和正式隐私说明。
- 完成备份恢复、访问隔离、删除、限流、成本和运行监控检查。

通过标准：账号数据不会串用，迁移不重复或丢失，用户能导出与删除；完成真实用户走查后再确定发布门槛。

## 8. 本轮未决定事项

- 当前持久化参考实现为 PostgreSQL，Cloudflare Workers + D1 已用于隔离预发布；生产迁移、认证与对象存储方案仍待选择；
- 原始探索回答的服务端保留时长、数据区域与备份删除期限；
- 匿名用户跨设备方式、正式离线范围和账号恢复流程；
- 百炼新加坡已选为初始模型供应商且只能使用 Free Quota Only；具体模型白名单、边缘/按主体限流及真实用户开放范围仍需上线前验证。

这些选择会产生费用、外部数据处理或账号迁移，实施前单独确认。架构和领域契约不依赖某一家供应商。
