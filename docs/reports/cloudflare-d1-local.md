# Cloudflare D1 本地写入验证

- 日期：2026-09-12
- 范围：Wrangler 本地 D1 迁移、Worker HTTP、确认档案、完整工作区对象、导入、证明、batch 启动/导出读取、条件级联删除、幂等重放与并发冲突。
- 不包含：Cloudflare 登录、远程 D1、部署、Pages 路由、工作区写入、模型网关或真实用户数据。

## 结果

Wrangler 4.131.1 在临时持久目录中成功应用 `0001_foundation.sql`，10 条 SQL 全部成功。真实本地 Worker 随后完成：匿名会话创建、首次确认档案写入、原幂等键响应重放，以及两个相同 revision 的并发写入。并发结果严格为一个 200 和一个 409，读取到的最终档案 revision 为 2。更新后的同一专项又覆盖路径创建与重放、计划创建和归属、路径移河后计划河流联动、空工作区导入、成长记录、证明确认/重放/撤回，以及工作区同 revision 并发仍严格为一个 200 和一个 409。最终 bootstrap 和导出通过 D1 batch 返回档案与 revision 4 的工作区；陈旧删除返回 409，正确版本删除成功，旧会话随后返回 401。

真实删除首次暴露 D1 `changes` 会包含外键级联删除的多行，原先“必须等于 1”的判断会在数据实际删除后误报 404。实现已改为至少一行即成功，模拟 D1 也固定返回多行级联计数以防回归。

验证入口为 `scripts/check-cloudflare-local.mjs`；它只写合成内容。模拟 D1 单元回归继续覆盖缺少绑定、免费行额度耗尽、损坏 JSON、主体隔离和请求边界。`npm audit` 在升级 Wrangler 后对完整依赖树和仅生产依赖均报告 0 个已知漏洞。

## 安全纠正与限制

首次本地启动发现 Wrangler 会在没有 `.dev.vars` 时回退加载根 `.env`。变量值在输出中保持隐藏，当前 Worker 没有模型路由，验证期间未发生供应商调用。项目现保留空的 `.dev.vars.example`，本地运行前复制为被 Git 忽略的 `.dev.vars`，防止 Node/PostgreSQL 或百炼变量被无关注入。

本次证明的是当前工具版本和单机本地 D1 行为，不等于远程 D1、跨地域并发、故障恢复、额度报警或生产发布验收。下一步推进模型网关、边缘限流、账号、备份恢复与远程预发布验证。
