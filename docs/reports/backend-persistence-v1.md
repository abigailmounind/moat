# 后端持久化首轮验证

日期：2026-09-10。范围：用户确认后实施首轮“持久仓储 + 路径/计划对象读写”，未接入账号、付费服务或真实 AI。

## 实现

- 安装并锁定服务端 `pg` 驱动；增加 PostgreSQL 迁移、连接配置、启动迁移检查和连接池关闭。
- 增加主体、会话、空档案、工作区版本、路径、计划、路径归属、成长记录和幂等回执表。里程碑、行动与证明快照暂保存在对象 JSONB 中。
- `/api/v1/paths`、`/api/v1/plans` 提供创建、读取、完整更新和删除。对象写入使用必填幂等键与工作区 revision。
- 抽取共享移河、删除、归属和历史上下文操作；前端保留兼容导出，服务端在仓储原子边界内执行操作校验。
- 写入先锁工作区再查回执，数据与回执同事务保存；跨表读取使用同一连接的固定快照；错误回滚后释放连接。
- 默认继续内存模式；显式 DATABASE_URL 启用 PostgreSQL，连接或迁移失败停止启动。网页继续本地保存，尚未同步或迁移。

## 实际验证

本机 PostgreSQL 17 镜像下载网络超时，改用已有 PostgreSQL 16.4-alpine 镜像。临时容器仅监听 127.0.0.1 随机端口；脚本在随机 schema 中写入合成数据，完成后删除该 schema，验证容器已停止。没有读取或迁移用户浏览器数据。

已通过：

- 全量 Node 回归（17 个测试文件），其中对象接口专项 6 个案例直接执行通过。
- 静态入口检查、JavaScript 语法检查与 git diff --check。
- HTTP 冒烟：24 个前端模块加载、会话隔离、并发重试与版本冲突。
- DOM：探索确认、本地保存、个人地图、方向带入与重复路径保护；成长快照确认、更新、撤回、删除及每河记录同步。
- 真实 PostgreSQL：并发迁移；两个连接池的 8 次同键并发只提交一次；不同写入版本冲突；回执重放及主体隔离。
- 真正 SQL 中途失败后的事务回滚，旧对象与版本保留，失败不写成功回执；修复后可使用原键重试。
- 在读取工作区版本和对象之间插入另一连接的提交，固定快照仍返回一致的旧版本；下一次读取返回新版本。
- 移河、删除路径、移除里程碑、删除计划时保留历史上下文与已确认证明；回执容量、到期以及会话到期。
- 实际启动 Node HTTP 服务、保存路径、关闭并再次启动；原 Cookie 恢复路径，原请求重放持久回执，继续建立计划。

事务设计核对了 [node-postgres 同连接事务](https://node-postgres.com/features/transactions) 与 [PostgreSQL 事务隔离](https://www.postgresql.org/docs/current/transaction-iso.html)；通过结论依据上述真实测试，不把参考文档当作测试证据。

## 当前边界与后续

工作区仍是并发单位，每次事务替换当前主体的工作区对象行；尚未实现每对象 revision、局部 SQL 更新和独立里程碑/成长/确认接口。聚合 PUT 保留原结构兼容，尚不能作为完整生产操作或任意迁移入口。

测试证明 Node 服务重启恢复，未执行 PostgreSQL 灾备、备份还原、跨设备登录或长期负载验证。没有新增页面布局，本轮 DOM 回归不代表浏览器视觉验收。当前 4173 预览仍为内存模式；数据库容器仅用于验证。

下一步是收口聚合写入用途，补成长/证明确认服务边界，并接入前端显式同步与本地迁移预览；成功前保留可靠浏览器数据。登录、云托管、导出删除与备份恢复继续按阶段推进。
