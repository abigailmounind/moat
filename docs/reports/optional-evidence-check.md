# 可跳过补充核对验证

日期：2026-09-11。范围：本地规则的具体方法与三河明确关系补充；全部使用合成输入，未接入模型或外部服务。

## 实现边界

探索在结果与来源后新增一页可跳过核对：用户可填写本次使用的具体知识、方法或工具，也可多选现实支撑、跨情境复用、自主投入三种明确关系。人力资本候选只读取具体方法；河流候选只读取用户明确选择，并允许同一经历关联多条河。未填写或未选择时记录为未知，经历类别、结果和决策卡点不再补出这些关联。

当前输入没有形成 R10 所需的自主目标与投入限制，因此规则不自动生成未来方向。用户仍可在未来路径工作区自主建立路径。手工整理入口继续只保存明确经历、行动和结果，不读取补充页生成关联。

探索会话版本更新为 `stage10-minimum-v0.2`，候选契约仍为 `0.1`。旧会话缺少新增问题时按 `not_asked` 保持未知，引用列表保持为空，服务端旧分析入口不会因悬空引用返回非法候选。

## 验证证据

- 24 个测试文件通过：覆盖七项回答转换、具体方法触发、经历类别不推河、河流多选、全部跳过、旧会话兼容、确认依赖、保存与服务边界。
- `scaffold-dom-check.mjs` 通过：补充页填写、动态确认、依赖重新确认、地图河流摘要及自主路径创建。
- 手工探索、工作区与阶段 11 DOM 专项继续通过；`npm run check` 检查 30 个浏览器模块及入口资源通过。
- 真实 Chromium 在 1440 × 900 填写补充依据，在 390 × 900 全部跳过；两种视口随后均完成手工探索到证明回流的连续闭环，没有页面异常、意外 API 请求或横向溢出，并启用减少动态效果。

临时浏览器缺少中文字形，截图不能用于字体视觉验收；390px 为触控模拟，不等于实体设备。当前规则只验证结构、来源和确定性行为，不证明用户自述事实或内容质量已经通过真实用户研究。
