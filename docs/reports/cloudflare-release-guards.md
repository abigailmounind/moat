# Cloudflare 发布保护验证

- 日期：2026-09-12—13（跨日完成验证与交接）。
- 范围：本地 Worker/D1 发布保护；无真实模型请求，无云端写入、发布或套餐变更。
- 工具链：项目锁文件中的 Wrangler 4.131.1，复用其 esbuild、Miniflare/workerd；没有新增运行依赖。

## 实际改动

1. 新增 `0002_release_guards.sql`：既有回执补充请求所有权，增加索引、模型窗口计数及在途锁；保留第一版迁移和旧回执。个人计数与锁参与主体删除级联，全局计数独立保留。
2. 档案/工作区通过单事务清理过期键、占用共享键与容量、条件更新及读取首次响应。同键重试只提交一次；补上回执读取和文档读取之间的竞态处理。事务失败不残留成功回执。
3. Worker 接入规则与默认关闭的多模型分析路由，复用已有新加坡供应商与候选校验。公开模式缺少保护绑定时拒绝请求；模型要求全部开关及配置通过，实际供应商尝试前用 D1 预占全局日名额，每主体另有小时上限和在途锁。
4. 输入使用实际流式字节上限，供应商仅接收本轮允许字段；端点拒绝额外凭证、端口、路径、查询和重定向。Key、提示词及 IP 不落入新增数据库表。
5. 自动隔离发布检查负责打包、临时数据库、迁移、HTTP、事务/模型专项和运行时重启；无须读取真实配置。手动 HTTP 检查只接受回环地址并设置超时，避免误指生产。

第一次加入重启专项时发现 Miniflare 5 的 V4 配置转换不继承 `d1Persist`，重启后得到空数据库；已显式配置该工具版本的持久根并重跑通过。这是测试装置配置修正，未对用户数据执行迁移或清理。专项结束自动删除本次创建的临时合成数据库目录，现有本地 D1、`.env` 和云端资源未动。

## 完成边界与下一步

这些结果证明本地事务与协议保护可运行；不代表远程 D1 多地域行为、Cloudflare Free CPU/请求限制、账号恢复、真实浏览器布局、实体触控、真实模型质量或用户验收完成。本轮未重新执行 PostgreSQL 专项；共享供应商的模拟回归包含在全量测试中，Node + PostgreSQL 保留。
