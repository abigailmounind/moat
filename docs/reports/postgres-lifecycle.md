# PostgreSQL 数据生命周期验证

日期：2026-09-11。

## 范围与环境

按用户本次确认，优先完成 PostgreSQL 真实验证与数据生命周期，再推进身份和跨设备。Workers/D1 暂不作为主线。保留本地闭环的历史验收及已有工作区改动。

复用本机 PostgreSQL 16.4-alpine 镜像，启动仅监听 127.0.0.1 随机端口的独立临时容器。每次 check:postgres 创建随机 schema，写入合成数据，结束删除该 schema；验证结束停止自动移除的容器。未访问浏览器个人数据、既有数据库或生产服务。

## 本轮改动

- 新增 `tests/fixtures/postgres-lifecycle-check.mjs`，由 `scripts/check-postgres.mjs` 调用。
- 在导入、成长创建/编辑/删除、证明确认/撤回的回执写入处注入真正 SQL 错误：此前数据行及版本已修改，必须完整回滚；核对没有成功回执，原键重试成功且后续重放不重复写入。
- 在删除主体前、成长行已删除后注入 SQL 错误，核对成长记录、版本、会话及历史回执恢复。
- 通过持锁闸门覆盖写入先取得锁、删除先取得锁两种顺序；分别要求陈旧删除被拒绝、删除后的写入被拒绝。
- 增补实际 HTTP：保存成长并确认证明，重启 Node 后重放原回执、导出完整快照、拒绝陈旧删除，成功删除后再重启并核对旧会话无效、数据不存在。

所有新增检查通过，未发现需要修改业务逻辑的缺陷；本轮仅增加验证代码与同步文档。

## 实测结果

最终 `npm run check:postgres` 全部通过，包含已有及新增范围：

- 并发迁移及 schema 校验；两个连接池的并发写、幂等、版本冲突和主体隔离。
- 成长、证明和空工作区导入的共享专项；六种操作失败回滚、无成功回执、原键重试。
- 一致性读取、关系修改、历史快照保留、回执容量及过期、会话过期。
- 导出副本隔离，主体删除及八张关联表清理；删除失败回滚及写入/删除竞争。
- 真实 HTTP 路径/计划、成长证明、导出与删除，Node 服务重启后的会话、内容和回执恢复及删除保持。

`npm test` 通过：运行器报告 22 个测试文件，0 失败；此处不将文件数当作内部用例数。`npm run check` 通过：30 个前端/共享模块语法及入口、资产、动效保护检查。两个变更脚本单独通过 Node 语法检查。差异空白检查通过。

## 剩余边界

本轮为本地真实 PostgreSQL 和 Node HTTP 验证，不等于生产环境或用户验收。未验证 PostgreSQL 备份还原、数据库故障切换、长期负载、真实浏览器同步/下载/删除、账号及跨设备。

下一步推进身份与匿名转账号方案，并贯穿真实浏览器验收；认证供应商与外部接入尚未确定。服务端探索档案仍无写入接口，本轮导出范围仍为当前服务端主体数据，不含独立浏览器探索档案。没有提交 Git、部署或调用真实模型。
