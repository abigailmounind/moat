# Pages 同源 API 接入验证

- 日期：2026-09-13。
- 范围：可选 Pages API 产物、同源适配器、本地实际服务绑定、隔离预发布准备。
- 授权边界：继续工程和本地验证；未创建云端资源、迁移远程数据库、部署、上传 Secret 或调用真实模型，现有生产 Pages 未改。

## 实际改动

- `cloudflare/pages-worker.mjs` 仅通过 `MOAT_API` 服务绑定转发 API，保留 Pages URL、Origin、Cookie、IP、请求体及幂等键；无任意上游 URL，禁止重定向，拒绝非 JSON 伪成功。故障返回可重试 503，不回落静态首页。
- `pages-routes.json` 只包含 `/api` 和 `/api/*`。`build-pages.mjs --with-api` 才加入 `_worker.js` 与 `_routes.json`；默认仍是原静态打包。打包不复制 backend、数据库配置、环境文件或依赖目录，也不部署。
- 新增 Pages staging 配置模板及后端 `env.staging`：独立 D1/限流桶、模型关闭、Worker 公共地址关闭；服务绑定目标一致，真实 ID/账号尚未配置。
- 新增自动本地双 Worker + D1 专项；原静态 HTTP 检查增加可选 `--require-api` 只读首轮规则版发布检查，不建会话、不写数据、不开模型。

## 工具装置修正与限制

当前安装的 Miniflare 工具链不接受本地跨日后的 2026-09-13 兼容日期，沿用现有 Worker 的 2026-09-12 固定日期。其静态路由配置还要求显式 `has_user_worker`，缺少时返回 500；定位并补齐后重新走完全部本地专项，没有通过修改产品 Origin 或降低限流绕过问题。

本地专项使用 Miniflare 静态资产路由承载 Pages 输出，并按 `_routes.json` 的 include 配置调用用户 Worker；这不是远程 Pages 路由控制台。Pages 专用文件从本地静态资源副本中排除。Cookie 检查覆盖请求转发、属性、响应和失效协议，连接夹具手动管理 Cookie，不代表真实浏览器接受/发送 Cookie 已验收。本轮未做 UI/视觉改动，也未运行真实浏览器、实体触控或远程多地域验证。

只读健康/能力检查不执行数据库写入、不核对 Cloudflare 套餐，不能替代远程合成数据端到端、Free 限制与备份演练。远程必须确认独立账号/资源目标、Pages Fail closed 和访问范围；部署清单见 [隔离预发布准备](../../cloudflare/README.md#隔离预发布准备)。现有 `themoat` 生产 Pages 及 Node + PostgreSQL 保留。
