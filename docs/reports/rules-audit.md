# 本地规则依据审查

日期：2026-09-11。范围：源码、现有规范与合成输入走查；本轮仅规划文档，无运行时修改。

## 核对发现

| 位置 | 当前行为 | 风险及后续修正 |
|---|---|---|
| exploration-domain.js / riverProposal | q2 的 interest 卡点直接触发 love | 该选项实际含义是“还没找到愿意投入的方向”；必须停止把缺失方向当作热爱依据 |
| 同上 | work、reality、continue 触发 survival，其余兜底 ability | 情境与决策卡点不足以决定证明归属；改为明确依据/手工核对 |
| runSyntheticAnalysis | 输入非空后固定产生 human、河流和方向 | 动词和类别不足以判断资本；候选允许为空 |
| 同上 | unclear 也是非空结果，方向仍称“提供了具体行动与结果” | 区分报告行动、成果与效果未知，不能模板补齐成果 |
| 同上 | 河流/方向引用全部存在的 q1–q5 | 引用题目存在不代表其支持判断；需引用实际依据 |
| exploration-review.js / confirmReview | 删除证明只过滤资本、河流；方向独立保留 | 方向仍可能声称已有支持；需要显式依赖与失效处理 |
| shared/understanding.js | 格式、枚举、ID 与引用检查 | 不能证明文本有依据，也不能核实自述；内容评测另建 |
| tests/scaffolds.test.mjs | 删除经历案例明确断言仍保留一个方向 | 是当前行为回归，不应当作新规则正确性的证据；实施依赖修复时同步调整 |

## 合成走查证据

通过 Node 直接调用当前 runSyntheticAnalysis 和 confirmReview，未访问存储、网络或个人数据：

- 项目 + 整理信息 + 完成成果 + “没有方向”卡点：输出 love、人力资本，以及“已有兴趣与行动线索”。
- 同样项目、行动、成果 + “现实条件需照顾”：输出 survival 及现实支撑方向。
- 项目 + 整理信息 + “暂时没有明确结果”：输出 ability、人力资本，方向仍声称提供了具体行动与结果。
- 三例均先保留条目再删除经历：确认证明为 0，方向仍为 1。

以上是缺陷复现，不是测试通过或用户验收。未运行无关全量测试，未生成资产。

## 处理依据与交付

用户本次明确要求规则不能无依据套模板，优先于旧探索规范中把卡点/经历类别直接映射河流的描述。现有本地闭环历史验收保留，内容推断问题单独修订；不将新规划误写为已实现。

新 [规则规范](../RULES_SPEC.md) 包含十类规则、依据及依赖要求、缺失/冲突处理、十六个正反验收案例和四个实施切片。首个切片应收紧不成立的推断，再补输入与追溯能力。本轮未修改旧档案、运行规则或测试断言。
