# 工作区规范 · 路径、计划、里程碑与成长记录

- 用途：字段、归属、保存删除、成长快照及方向桥接的当前本地实现规则。
- 最后更新：2026-09-10。整体验收状态见 [进度表](../milestones.md)。
- 模块、依赖与校验分层见 [工程规范](ENGINEERING_STRUCTURE.md)，服务端聚合与路径/计划对象写入见 [API 契约](PRODUCT_API.md)。本规范的当前保存流程仍基于浏览器，尚未迁入服务端。

## 1. 入口与层级

`/?view=paths`、`/?view=plans`、`/?view=growth` 分别进入未来路径、护城河计划和成长记录。复用三河地形、暖纸与色彩，不改造主图 SVG。

从主导航进入路径与计划页时先显示概览。概览隐藏右侧详情或编辑区，让河流轴使用完整内容宽度；进入时展开三条河及计划页的全部路径，之后仍可逐项收起。选择一个路径或计划会进入详情视图；携带具体对象的跨页入口可直接打开详情或编辑。
右上角“概览”进入时清除选中态。已保存详情右下角收起详情，或编辑后保存并查看概览时，保留当前节点选中，以显示它在完整河流轴中的位置。
编辑路径、计划或里程碑时可以普通保存，也可以“保存并查看概览”；两者使用同一校验和写入规则，只有保存成功后才切换视图。

计划页始终提供「新建计划」入口。已有路径时打开计划草稿，要求明确选择归属；没有路径时说明依赖并提供各河「先新建路径」链接，进入对应河的路径编辑器，路径保存后可从详情继续新建计划。切换站点不会自动带入旧站点的浏览器工作区。

**河流 → 未来路径 → 护城河计划 → 里程碑 → 成长记录。**

三河组织路径；每条路径可有多个计划。新建计划必须明确属于一条路径并继承其河流。计划编辑器默认使用进入时或上次保存的河流，也允许先切换河流，再从该河的路径中重新选择归属；不能保存河流与路径不一致的计划。路径和计划是长期工作区；计划围绕五资本积累，不以单一任务清单替代资本目标。

## 2. 字段与基本操作

| 对象 | 字段 | 行为 |
|---|---|---|
| 路径 | 名称、河流、状态、目标、支持、缺口、现实条件、验证行动、备注 | 增改删；两到三条并列比较，不打分排名 |
| 计划 | 名称、所属河流、状态、资本目标、至少一项资本、路径、里程碑、备注 | 增改删；改河时重新选择同河路径；详情显示关联成长记录 |
| 里程碑 | 名称、完成标准、有序行动、独立完成标记 | 详情直接添加与编辑，也可随计划编辑；支持移除和上移 |
| 行动 | 文字、独立完成状态 | 编辑时每行一项；未改写的行动保留完成状态 |
| 成长记录 | 标题、日期、类型、行动、成果、复盘、来源、可选计划与里程碑 | 按时间、河流、路径回看；里程碑来自所选计划 |

完成行动不自动完成里程碑，完成里程碑不自动新增证明、资本或改变河宽。计划和里程碑可直接带入成长记录填写。

## 3. 旧数据与归属变化

| 情况 | 当前处理 |
|---|---|
| 旧独立计划 | 保留内容并放入待归属区；编辑不自动选择第一条路径 |
| 旧同河多路径计划 | 可保留已有关联，详情显示全部路径；新增计划仍只允许一条路径 |
| 旧跨河或河流不一致计划 | 待明确归属，不自动拆分、换河或选择路径 |
| 移动路径到另一条河 | 提示影响；单路径计划同步继承新河流；跨河共享旧计划保持待归属 |
| 删除路径 | 计划与里程碑保留，移除该路径关联；无有效归属时进入待归属区 |
| 删除计划或里程碑 | 解除成长记录对应活动关联，保留历史名称与已确认快照 |

成长记录保存路径名称和河流的分组上下文。有有效活动关系时读取当前归属；删除父项后可按保留上下文回看。旧数据后续写入时补足上下文，不整体迁移；移动路径不自动改变已确认证明的河流关联。

旧同河多路径是兼容已有数据的实现边界，不意味着新建流程重新开放多路径计划。

## 4. 保存、草稿与失败

使用独立浏览器键 `personal-moat:workspaces:v1`，与探索档案、合成案例分开。默认空数据；自由文本按文本转义显示。

展开河流或路径、切换成长记录分组时保留编辑输入。切换正在编辑的记录、创建另一项或离开有修改的表单时处理放弃确认；刷新使用浏览器离开提醒。当前未实现自动草稿恢复。

保存失败保留当前草稿和旧数据；勾选完成写入失败时回到原值。损坏或未知版本档案阻止覆盖。版本与条目检查拒绝已检测到的陈旧提交，部分独立条目更新可以合并；localStorage 没有严格同时写入的原子事务。

删除前说明影响并确认，当前没有删除撤销。错误不能显示保存成功。工作区与快照结构校验位于 `shared/workspace.js`、`shared/profile.js`；移河、删除与历史上下文共用 `shared/workspace-operations.js`；前端保存和表单规则继续位于 `frontend/src/workspace-model.js`、`frontend/src/workspace-form.js`。

结构校验为旧档案保留兼容性，操作层另外限制新建归属、移河和删除影响。后端路径/计划对象接口现已在仓储原子边界内复用这些操作规则；里程碑随完整计划内容更新，成长记录仍通过聚合契约兼容。服务端 API 当前与浏览器档案独立，幂等回执也不会自动为本地表单提供同步或恢复。

## 5. 成果证明快照

成长记录包含具体行动与成果后，可以“保存为证明”。用户核对内容，可选一项资本、一条河流；默认不选，选中必须补充解释。计划目标、选择某条路径和完成标记不能替代支撑依据。

确认快照保存在成长记录的 `proof` 字段，与记录同键写入。地图合并读取探索档案和这些快照，不把快照复制到探索存储。

| 操作 | 对地图和原记录的影响 |
|---|---|
| 首次确认 | 保存当前行动、成果、来源与可选关联 |
| 修改原成长记录 | 保留原快照，提示再次确认才能更新地图 |
| 再次确认 | 替换同一证明与关联，移除此次不再保留的关系，不重复新增 |
| 撤回证明 | 移除快照与关联，保留成长记录 |
| 删除成长记录 | 同时移除其快照与关联 |
| 删除计划、路径或里程碑 | 保留成果快照，不随活动归属自动改写历史证明 |
| 写入失败或原记录已被他页修改 | 保留可靠数据与草稿，拒绝陈旧确认 |

地图详情可回看原成长记录。成果回流只表示新增或更新证据信息，不增加资本分数、改变河宽、生成分叉或清除雾。

“我的河”的每条河摘要同步显示该河已保存的路径和有效归属计划，并可回到对应详情；地图同时以空心圆路径节点和菱形计划节点显示它们的所属河流。路径与计划在这里作为工作区记录呈现，不作为证明，也不会改变资本、河宽或雾；待归属及河流不一致的旧计划不放入任一河流。

## 6. 候选方向转路径

探索中已确认并保存的方向，从地图详情带入路径草稿：名称、河流、支持、缺口与下一步。用户核对并点击保存后才建立长期路径，不自动创建计划。

路径记录来源方向标识；同一方向再次进入时打开已有路径，保留用户编辑。检测到另一页面已经建立该方向路径时拒绝重复保存。来源标识用于防重复，不表示后续分析可自动同步或覆盖路径。

删除探索证明不会级联删除已建立的长期路径。真实模型重新分析后的语义差异比较仍未实现。

## 7. 验收路线与限制

路径保存和比较 → 在路径下建计划 → 添加并编辑里程碑与行动 → 记录成果 → 确认快照 → 我的河查看及回看原记录 → 修改后重新确认 → 撤回或删除。

同时复核旧归属、路径换河、历史分组、文本安全、失败重试、陈旧提交与草稿保留。河流轴展开密度、长表单、窄屏、键盘、触控与视觉一致性仍须实际页面验收。

页面当前无真实模型、账号、云端或跨设备同步；可选 PostgreSQL 服务端仓储已有路径/计划对象切片，尚未迁移浏览器数据；自动检查与限制见 [后续骨架报告](reports/next-foundation.md)，早期回流证据见 [阶段 11 报告](reports/stage11-verification.md)。


## 服务端数据管理

数据与同步页仅在已有服务器连接时提供服务端导出与删除。先导出并核对工作区范围，再次确认删除；成功清理当前浏览器的服务器缓存，原始本地工作区和探索档案保留。若请求结果不明，持久化待核对标记并暂停服务器操作；独立清理缓存需要用户再次明确确认，不代表服务端删除已确认。下载交给浏览器不等于文件已保存成功。其他标签的旧草稿遇到失效会话不得显示保存成功。

删除或切换连接后，其他标签仍可能显示旧草稿。连接层拒绝已标记快照跨保存位置或主体提交；需保留文字并重新核对当前工作区，不能把旧服务器草稿自动写入原始本地副本。
